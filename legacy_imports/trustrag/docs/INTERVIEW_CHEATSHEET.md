# TrustRAG 面试速查表

## 🎯 四大维度回答框架

### 1️⃣ 前沿技术应用

**检索技术栈：**
- BGE-M3：8192 tokens长文本，1024维向量，多语言原生支持
- HyDE：假设性文档嵌入，解决查询-文档语义鸿沟
- BGE-Reranker v2：大模型重排序，+20-40%相关性提升

**模型优化：**
- TensorRT FP16：GPU推理2-4x加速
- vLLM PagedAttention：LLM推理3-5x加速
- Flash Attention 2：注意力计算2-3x加速
- 动态批处理：请求聚合，提升吞吐量

**多模态理解：**
- DETR：图表检测与分类
- ChartOCR + LayoutLM：元素提取
- GPT-4V / Qwen-VL：语义理解
- 跨模态验证：图表vs文本一致性校验

### 3️⃣ 规模化思考

**架构演进：单体 → 云原生微服务**

| 服务 | 职责 | 扩展策略 |
|------|------|----------|
| query-service | 查询路由 | HPA (CPU) |
| retrieval-service | 向量检索 | HPA (QPS) |
| embedding-service | 文本编码 | HPA (GPU) |
| judgment-service | 证据仲裁 | HPA (CPU) |
| multimodal-service | 图表理解 | HPA (GPU) |

**三级缓存架构：**
- L1 (In-Memory): ~1ms, 1GB/Pod, 热门查询向量
- L2 (Redis): ~5ms, 100GB, 检索结果缓存
- L3 (SSD): ~20ms, 1TB, 文档块缓存

**性能提升：**
| 指标 | 优化前 | 优化后 | 提升 |
|------|--------|--------|------|
| 冷启动 | 15s | 3s | 5x |
| QPS | 10 | 1000+ | 100x |
| P99延迟 | 500ms | 200ms | 2.5x |

### 4️⃣ 技术创新

**核心创新点：**

| 创新 | 描述 | 价值 |
|------|------|------|
| 认知隔离2.0 | 多模态也遵循认知隔离 | 业界首创 |
| 自适应多路召回 | 动态调整召回权重 | 长尾+25% |
| 跨模态验证 | 图表vs文本交叉验证 | 消除幻觉 |
| Shadow A/B | 新旧算法并行对比 | 零风险迭代 |

**认知隔离2.0原理：**
```
传统RAG: Query → LLM提取数值 → 可能幻觉
认知隔离: Query → 确定性规则提取 → LLM仅渲染语言 → 零幻觉
认知隔离2.0: 扩展到多模态，图表理解也遵循认知隔离
```

## 💬 面试话术模板

### Q: 这个项目最大的技术挑战是什么？

> "最大的挑战是如何在保证零幻觉的前提下提升检索召回率，尤其是长尾查询。
> 我们的解决方案是多路召回融合+自适应权重学习：
> 1. 5路并行召回覆盖不同查询模式
> 2. 基于查询特征动态调整权重
> 3. 用户反馈驱动持续优化
> 最终将长尾查询召回率从60%提升到85%。"

### Q: 如何保证系统的可扩展性？

> "我们采用云原生微服务架构：
> 1. 服务拆分：8个独立微服务，按职责划分
> 2. 弹性伸缩：Kubernetes HPA，根据负载自动扩缩
> 3. 分布式存储：Milvus集群支持十亿级向量
> 4. 多级缓存：L1/L2/L3三级缓存，冷启动从15s优化到3s
> 5. 异步处理：动态批处理提升吞吐量
> 最终QPS从10提升到1000+。"

### Q: 如何处理多模态数据？

> "我们设计了四阶段多模态理解Pipeline：
> 1. 图表检测：DETR识别图表类型
> 2. 元素提取：ChartOCR提取数据点
> 3. 语义理解：VLM生成结构化描述
> 4. 跨模态验证：图表数据与文本交叉校验
> 关键创新是将认知隔离扩展到多模态，图表中的数值也由确定性规则提取，
> VLM仅负责语义理解，从架构上消除多模态幻觉。"
