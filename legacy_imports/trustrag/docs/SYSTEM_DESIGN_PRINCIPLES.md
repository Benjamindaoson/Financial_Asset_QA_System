# TrustRAG System Design Principles

本文档定义了 TrustRAG 的核心系统设计原则，涵盖失败分类学、权衡策略、系统边界与跨配置稳定性。

---

## 1. 失败分类学（Failure Taxonomy）

在 TrustRAG 中，**并未以整体回答准确率作为唯一优化目标**，而是显式定义并持续追踪**高风险失败模式（Failure Modes）**，将系统优化目标聚焦于**高影响错误的系统性消除**。

### 核心失败类型定义

| 代码 | 名称 | 定义 | 严重性 |
|------|------|------|--------|
| **F1** | 数值幻觉错误 | 回答中出现无法追溯至证据来源的数值或比例 | Critical |
| **F2** | 指标口径错配 | 同一指标在 YoY/QoQ、GAAP/Non-GAAP 等口径下发生混淆 | Critical |
| **F3** | 时间范围错误 | 查询时间表达不明确或被错误解析，导致使用错误周期的数据 | High |
| **F4** | 权威性违背 | 低权威来源（如电话会表述）覆盖高权威来源（如 10-K 正式披露） | High |
| **F5** | 证据不足推断 | 在证据缺失、冲突或不充分的情况下给出确定性结论 | Critical |
| **F6** | 不安全回答 | 对本应拒答的越界、前瞻性或不可披露问题给出回答 | Critical |

### 设计原则

> **系统评测与演进的核心目标，是最小化上述高风险失败模式的发生率，而非单纯提升平均回答质量。**

每一次系统变更，均需通过黄金评测集验证上述 6 类失败模式的发生率是否上升。任何导致 F1/F2/F5/F6（Critical 级）失败率上升的变更，均视为回归，不可合并。

---

## 2. 成本–风险–正确性权衡策略

TrustRAG **并未将成本或延迟作为单一优化目标**，而是显式引入**"决策风险"作为核心调度变量**。

### 权衡原则

1. **对低风险、确定性查询**（如已验证财务数值、规范化指标），优先采用确定性路径（FastPath / DerivativePath），避免不必要的模型调用。

2. **对高风险或高影响查询**（涉及跨文档冲突、口径歧义、合规边界），系统会主动分配更多计算资源与校验步骤，以降低潜在错误带来的业务风险。

### 设计宣言

> **系统在设计上有意识地牺牲部分成本与时延，以换取关键决策场景下的正确性与安全性，而非追求整体调用成本的最小化。**

### 实现路径

```
查询输入
    │
    ▼
┌───────────────────┐
│  Pre-Judgment Gate │  ← 风险评估 & 路由决策
└───────────────────┘
    │
    ├── 低风险 → FastPath (0 LLM, <50ms)
    │
    ├── 中风险 → DerivativePath (0 LLM, <100ms)
    │
    └── 高风险 → Full RAG Path (多轮仲裁, 200-500ms)
```

## 3. 系统边界与非目标（Non-goals）

TrustRAG 的设计目标**并非覆盖开放式对话或创造性生成场景**。系统在架构层面明确排除以下能力作为非目标：

### 明确不做的事情

| 非目标 | 说明 |
|--------|------|
| ❌ 开放式推理 | 不进行预测性判断或主观分析 |
| ❌ 超范围回答 | 不对未披露、前瞻性或超出证据范围的问题给出结论性回答 |
| ❌ 对话流畅性 | 不追求生成多样性或对话连贯性，优先保证结论的可验证性 |
| ❌ 创意生成 | 不生成营销文案、创意内容或情感化表达 |
| ❌ 实时数据 | 不处理实时行情、盘中变动等非存档数据 |

### 边界行为

> **当查询超出上述系统边界时，TrustRAG 将主动拒答并返回结构化的拒答原因与适用边界说明，以避免"看似合理但不可验证"的输出进入业务流程。**

---

## 4. 跨模型 / 跨配置稳定性

TrustRAG 的核心设计目标之一是**降低对特定模型或配置的依赖**，确保系统的可靠性不因底层组件变更而崩溃。

### 稳定性保障机制

| 层级 | 组件 | 稳定性策略 |
|------|------|-----------|
| **Embedding** | 向量模型 | 规范事实库（Canonical Fact Store）不依赖 embedding 相似度，而是精确 key 匹配 |
| **Reranker** | 重排序模型 | Rerank 仅作为辅助信号，核心决策依赖证据绑定与数值校验 |
| **LLM** | 生成模型 | LLM 仅负责"语言渲染"，不参与数值计算或事实判断 |
| **OCR** | 文档解析 | 支持 PaddleOCR / Tesseract 双引擎，结果可交叉验证 |

### 设计宣言

> **系统的核心正确性保障来自确定性规则与证据绑定，而非依赖特定模型的"涌现能力"。当更换 LLM、Embedding 或 Reranker 时，系统行为应保持一致，仅在响应延迟或成本上产生差异。**

### 验证方法

1. **黄金评测集回归**：每次模型变更后，重放 54 条黄金查询，验证 Pass Rate 不下降。
2. **跨模型 A/B**：支持在相同查询上对比不同模型的输出，确保核心判断一致。
3. **Embedding 降级测试**：在 embedding 服务不可用时，系统自动降级至关键词匹配，仍可返回确定性事实。

---

## 总结

TrustRAG 不是一个"追求平均正确率"的系统，而是一个**"系统性压制高风险错误"**的决策基础设施。其核心竞争力在于：

1. **失败分类学**：明确定义 6 类高风险失败模式，作为系统演进的红线。
2. **风险驱动权衡**：低风险省算力，高风险多投入，而非一刀切的成本优化。
3. **边界自知**：明确声明"不做什么"，拒答是一等能力。
4. **组件解耦**：核心正确性不依赖任何单一模型，支持热切换与降级。
